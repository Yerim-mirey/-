## 人工复核与机器误报

**S2 / A4（设施范围）**：自动检出“生鲜超市”“超市”，原句是“菜市场类别中包含生鲜超市、社区菜市等不同业态”。诊断的菜市场 POI 清单中确有“盒马鲜生”“亿忆鲜生鲜超市”等名称；这里讨论的是菜市场检索结果的类别有效性，后续行动仍仅针对菜市场、药店、小学，没有要求新建或配置超市。按 A4 标准判 **pass**。

**S2 / A5（数字与证据）**：自动评分把建议中的“三类设施的盲区比例均在 90% 以上”解析为“必须恰好等于 90.00%”，因而判 fail。实际盲区比例分别是菜市场 **96.3167%**、药店 **91.2205%**、小学 **91.5672%**，均严格高于 90%。正文的“约 96.3% / 91.2% / 91.6%”、覆盖比例“约 3.7% / 8.8% / 8.4%”、覆盖/盲区网格数 **4/46、6/44、5/45**、15 分钟内确认可达数均为 0，也与诊断结果一致。按 A5 标准判 **pass**。机器原判及触发句仍保留在评分 JSON 中。

**S2 / A8（Reviewer）**：机器的 A8 fail 完全由上述 A5 fail 派生。A5 复核为 pass，Proposal 证据引用与设施类别吻合，Reviewer 的 `approved` 未发现量表所列的漏放缺陷，故 A8 判 **pass**。这只评价量表内的一致性，不证明规划建议在现实中适宜。

**S3 / A7（限制说明）**：运行警告为 `PARTIAL_ROUTING_RESULTS`。Proposal 的摘要明确写“部分步行路线数据存在不可用情形”，限制说明又写“存在部分目标点与部分网格步行路线不可用的警告，个别单元可达性判断可能受影响”。自动评分器只匹配英文 `partial` 或“不完整”，漏识别“路线不可用”，因此机器 fail 是关键词实现误报。按预定的“适用限制是否被声明”标准判 **pass**。S3 的建议只讨论菜市场与药店，A4 无越界命中。

S2/S3 的 Evidence、Proposal、Review 均存在且绑定本次运行，引用没有悬空或错配设施类别。没有发现 A3、A5、A6 三项关键项的实际失败。

## API 与前端读取这些结果时的语义

`completion_mode=normal` 表示规划／审查流程按正常路径完成，不表示所有证据源都完整；`confidence=high` 是当次 Diagnosis 的整体置信度字段，也不覆盖 warnings 中明确报告的路线问题。S3 的 `unknown_ratio=0` 表示没有网格被归类为 unknown，不代表全部路线请求成功。阶段状态、置信度、各设施类别的未知比例和非空 warnings 应并列呈现，不能用其中一个字段替代其余字段。若前端未来需要一个汇总“证据完整度”字段，应作为单独版本化的 API DTO 设计，不重解释现有字段。
