# Phase 10 语义抽样量表 v1（2026-09-23）

> 用途：把 Phase 10 退出条件里最后一项“真实语义抽样结论”从主观印象变成**可复核的记录**。
>
> **本量表在抽样之前写定**，检查项与判定标准先固定，再去看模型输出——避免“看完结果再决定怎么打分”。
>
> **归属必须说清**：本表由**同一模型**对真实运行的输出做自查，不是独立人工评估。它能发现明显错误与不一致，但**不能替代真人评审**，也不能证明“建议在现实中合理”。凡涉及“这个点位到底该不该补学校”一类现实判断，本表一律不给结论。

## 1. 抽样单位

一次完整规划运行（`run_agent`，`intent=planning_analysis`，走完 Diagnosis → Planning → Review）为一个样本。

记录键：`run_id`、中心点、设施类别、终态、`completion_mode`、warnings、算路目标数、耗时、模型调用次数。

## 2. 检查项（固定 8 项）

评分只允许 `pass` / `fail` / `n/a`。判 `fail` 必须写出**可复核的依据**（引用具体字段或数值），不接受“感觉不对”。

| # | 检查项 | 判定标准 | fail 的典型形态 |
| --- | --- | --- | --- |
| **A1** | 意图识别 | Brief 的 `intent` 与消息意图一致；“给出建议”类消息为 `planning_analysis` | 把规划请求判成普通查询 |
| **A2** | 设施归类 | `facility_types` 与消息中点名的类别一致；未点名时按标准三类 | 把“小学”归成其他类别、或漏掉点名的类别 |
| **A3** | 证据引用有效 | 每条 Proposal 的 `evidence_refs` 都存在于当前 bundle（确定性校验已保证，抽查确认无“指向不相关类别”） | 用市场证据支撑小学建议 |
| **A4** | 建议在设施范围内 | 建议只涉及 Brief 声明的设施类别，不引入其它设施或人口/用地结论 | 建议里出现“增设医院”“按人口密度布点” |
| **A5** | 数字与证据一致 | 正文引用的比例/距离/计数与对应 metric 一致 | 把 `blind=0.036` 写成“3.6%”以外的数值、或读错 `unknown` 与 `blind` |
| **A6** | 未知不当作已结论 | `unknown_ratio>0` 时，不得把“无盲区”表述为确定结论 | 把 `blind=0.0` 写成“确认无盲区”而不提未知网格 |
| **A7** | 限制被声明 | `limitations` 覆盖：置信度低、诊断不完整、未指定候选点位、未做情景模拟中**适用**的那些 | `confidence=low` 却完全不提 |
| **A8** | Reviewer 判断相符 | Review 的 `status` 与该 Proposal 的实际质量相符（质量有缺陷却 `approved` 即 fail） | 提案含越界建议却判 `approved` |

**分档（预先定义，不看结果再定）：**

- **合格**：A1–A8 全 pass，且至少 3 个样本；
- **有条件合格**：出现 ≤1 个非关键项 fail，且已记录成因与影响；
- **不合格**：出现任一关键项（A3、A5、A6）fail，或 ≥2 项 fail。

## 3. 抽样方法

**样本选择必须在跑之前定好，不能挑好看的。** 本量表固定一个 2 维设计：

1. **中心点**：至少 2 个**不同**坐标（不同街道，POI 与路网分布不同）；
2. **设施类别**：至少 1 个样本只问**部分**类别（不是默认三类），用于检验 A2/A4。

来源：复用 `scripts/verify_agent_live_e2e.py acceptance --include-diagnosis`，或 `agent "<消息>"` 单跑。每个样本都必须来自**真实百度数据**，不得用样例夹具。

**机械打分**：A1–A3、A5–A8 由 `scripts/sample_planning_quality.py` 从运行状态直接算出，取样时同时写出脱敏评分 JSON 与完整状态（完整状态含模型原文，只留在本机 `data/cache/`）。A4 抛出的命中句需人工读。

```bash
set -a; source .env; set +a
RUN_BAIDU_SMOKE=1 RUN_DEEPSEEK_SMOKE=1 python -m scripts.sample_planning_quality \
  --lng <经度> --lat <纬度> --facilities market,pharmacy \
  --report data/cache/sample-SN.json
```

样本消息里坐标**必须写明 BD09LL**：实测不写坐标系时模型会返回 `location=None`，运行停在 `waiting_for_input`，取不到规划样本。

**成本预告（诚实记录）**：每个含完整体检的样本约 1400–1600 个算路目标，按 3 目标/秒约需 **9 分钟**及对应百度配额。样本数直接决定配额消耗。

### 作废样本（不得计入结论）

**S2 与 S3 不是有效的语义样本，不能用来评价模型质量。** 两次运行都在**取证阶段**失败（`ISOCHRONE_FAILED`），失败原因是**出口 IP 换了、不在百度白名单**，不是模型行为，也不是地图数据缺口：

- 取样时出口 IP 从 `36.113.103.187` 变为 `223.160.206.240`（用户切换网络），百度对批量算路返回 HTTP 200 + `status=210`（`APP IP 校验失败`）；
- 该拒绝使所有算路目标都不可用，等时圈无法取得测时数据，于是诊断失败，规划与审查**根本没开始**；
- 因此 A3、A5–A8 记 `—`（不可评）而非 `fail`：它们不是被判定为不合格，而是**没有产出可评的对象**。

这也直接说明：**样本必须在白名单有效时采集**，否则会把环境故障误记成模型质量。

## 6. 当前结论

**尚未达到“合格”，因为有效样本只有 1 个（S1），而量表要求 ≥3。**

对 S1 一个有效样本：A1–A8 全 pass。但按本量表自己的规则，**n=1 不构成质量结论**，只能表述为“在这一个样本上未发现任何量表项缺陷”。S2/S3 因环境故障作废，需在白名单有效时重采。

## 7. 已知局限（随结论一起引用，不得省略）

1. **自查而非人工**：评分者与被评者是同一模型。A4/A7 这类需要外部判断的项，自查只能查“自相矛盾”，查不出“看起来合理但实际不该这么说”。
2. **有效样本量不足**：目前 1 个有效样本，未达本量表要求的 3 个，因此**不给出合格结论**。
3. **未评测现实合理性**：本量表**不判断**规划建议在城市规划意义上是否正确，只判断它是否忠于证据、是否越界、是否声明限制。
4. **仅覆盖规划路径**：普通设施查询与可达性提问不在本量表内（它们没有 Proposal/Review）。
5. **模型与日期绑定**：结论只对当时的模型（`deepseek-flash`）与数据集成立，换模型需重跑。
6. **环境依赖**：样本必须在其采集时的出口 IP 已加入百度白名单的前提下才算有效；IP 变更会让样本整体作废（S2/S3 即为此例）。
