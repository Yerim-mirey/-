# V2 自适应补查：首次真实综合测试

2026-09-28 对北京市海淀区学院路街道做了一次全目录生活圈诊断与规划提问。输入使用已验证的 BD09LL 坐标 `116.3582967,39.9995406`，省去地理编码调用；运行器仍按生产 V2 入口执行意图提取、设施检索、路线、诊断和规划。没有对整题重试。

| 项目 | 结果 |
| --- | --- |
| 运行终态 | `completed`（表示运行结束，不表示全部证据完整） |
| 耗时 | 10.49 秒 |
| 识别设施类别 | 45 类，规划意图正确 |
| 百度请求消耗 | 8 次地图请求、2 个路线目标，共 10 个共享配额单位 |
| POI 结果 | 7 个点位；2 类 `complete`、1 类 `partial`、42 类 `unavailable` |
| 路线 | 2 个目标，均返回可用步行路线 |
| 外部失败 | 百度 POI 检索返回 `RATE_LIMITED`；服务在此后停止追加查询 |
| 规划/审查 | 本次原始运行规划生成失败，审查未启动 |

这次记录了 88 条 `RATE_LIMITED` 查询状态，其中大部分是因限额而**没有发起**的后续关键词；它们不是 88 次实际百度请求。因主词阶段就遇到限额，自适应补查的额外关键词未在真实环境中得到验证；其顺序、预算和不完整状态由离线测试验证。本次结果不能说明其余 42 类设施不存在，也不能作为全目录覆盖验收。

实测后，V2 Runtime 增加了证据门槛：规划必需类别的地图检索为 `unavailable` 时，不再调用规划模型，返回 `PLANNING_EVIDENCE_UNAVAILABLE` 并明确提示地图限额。该修复已通过离线回归，未再次消耗百度额度进行整题复测。待地图额度恢复后，才适合做一次完整综合验收。

实测还暴露出路线抽样会先从全部目录类别预选名额，导致已有点位的幼儿园没有得到路线样本。Runtime 随后改为先筛出确实查到点位的类别，再在路线预算内均衡抽取；这项修复同样只做了离线回归，没有重跑百度路线。

离线复核时还补上了“全面体检，重点看药店”的意图解析：允许同时保留全目录范围与用户明确关注的设施，供补查预算排序使用；只问“诊断药店”的请求不会被模型扩大成全目录。该路径也尚未做真实地图复测。
