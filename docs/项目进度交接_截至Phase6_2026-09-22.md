## 一、项目背景与目标

项目面向社区“15 分钟生活圈”的智能体检和规划辅助。用户可提供社区地址、街道或明确的 **BD09LL** 坐标，询问菜场、药店、小学等设施的分布、步行可达性和服务盲区，或要求完整体检与有证据支持的改善建议。Core Diagnosis 默认按 15 分钟（900 秒）、1000 米步行服务距离及 200 米网格组织分析；实际空间事实由 Tool 计算。

系统职责已经冻结：**Tool 负责事实，Agent 负责理解、规划和审查，Runtime 负责流程。** Agent 不重新计算 GIS，也不直接访问百度地图 Provider。完整规划路径的目标是：

```text
用户 → Runtime → Orchestrator → LifeCircleBrief
     → Tool Gateway → Core Tool 1–6 → EvidenceBundle
     → Planning → PlanningProposal → Reviewer → ReviewResult
     → Runtime 决定完成、返工或补证据
```

当前只提供三类受支持设施：`market`、`pharmacy`、`primary_school`。数据中的 **`0` 表示确认没有，`null` 表示尚未查明或数据不完整**；不能把未知直接说成盲区或“绝对不存在”。技术基线是 Python、Pydantic v2、pytest、FastAPI、Shapely 和百度地图 Web Service；Agent 模型接口目前保持厂商中立。

## 四、目前已经做到什么程度

### Core 与 API

Core Tool 1–6 的契约和实现已在仓库，Diagnosis 负责组合前五个 Tool 的结果。FastAPI 当前仅封装 Core 的 `GET /health`、`POST /api/v1/location/resolve` 和 `POST /api/v1/diagnosis`，没有自然语言 Agent 入口。正式 Web、Docker 和 CI 尚未补齐。Core 详情见 [`README.md`](../README.md) 与 [`docs/architecture/core-mvp.md`](architecture/core-mvp.md)。

### Agent 与 Mock

- **Orchestrator：** 模型只提取意图、目标、地点、设施类别及是否属于标准三类设施范围；Python 生成工作标志和缺失信息。对不支持的设施先澄清，不偷偷替换成标准三类。
- **Planning：** 只根据完整 Brief 与成功 Diagnosis 证据提出问题和改善方向。代码要求设施指标覆盖请求范围、证据 JSON Pointer 可解析、坐标型 Brief 与诊断中心一致；建议必须引用输入证据 ID。地址型 Brief 到解析中心的绑定仍需未来 Runtime 保留 Tool 调用链来保证。
- **Reviewer：** 用公共 `ReviewResult` 三状态表达通过、返工或补证据；代码核对被审提案 ID、轮次、证据包 ID，以及审查问题所引用的建议/证据 ID。事实和数字是否真的被证据支持，当前依靠提示词，尚未经过真实模型评测。
- **Mock Gateway：** 不联网，按方法和规范化请求精确匹配 v1 样例；缺失场景显式报错。它供 Phase 7–8 接入和验证使用，不能当作真实地图验收。

### Runtime 已有部分

Phase 6 没有创建 Graph 或 Runner。`update_run` 返回新状态、不修改旧状态，禁止更改 run ID/原始消息/版本；**替换已有 Brief、Evidence 或 Proposal 时，即使 ID 不变也须清掉下游旧结果**，避免新证据沿用旧批准结论。`conditions.py` 的当前约定如下：

| 条件 | 返回值 |
| --- | --- |
| Brief 缺少地点或设施类别 | `wait_for_input` |
| Brief 完整 | `fetch_evidence` |
| Evidence 已有且需要规划 | `plan` |
| Evidence 已有且不需要规划 | `finalize` |
| Review = approved | `finalize` |
| Review = revision_required，未达 3 轮 | `plan` |
| Review = insufficient_evidence，未达 3 轮 | `fetch_evidence` |
| 非 approved 且达到 3 轮 | `finalize_with_limitations` |

`MAX_PLANNING_ROUNDS=3`、`MAX_TOOL_RETRIES=2`。`can_retry_tool` 只比较已重试次数；错误本身是否可重试，留给 Runner 判断。Agent 不自行调用彼此，也不决定下一节点。
